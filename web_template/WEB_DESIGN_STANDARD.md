# Web 设计标准

本模板采用开发工具工作台视觉语言：高信息密度、低装饰、强上下文阅读能力。首屏直接进入可操作界面，不做营销式 Hero。

## 设计目标

- 信息密度高，但层级清晰。
- 操作入口靠近当前上下文。
- 文档、证据和图谱可以长期阅读。
- Light / Dark 共享同一套语义 token。
- 中文、英文、路径、代码和长标题都能稳定展示。

## 布局标准

页面采用固定三栏结构：

```text
┌────────────────┬───────────────────────────────┬────────┐
│ SidebarConsole │ DetailSurface                 │ DocPanel│
│ 输入源与列表     │ 分析、评分、图谱、执行信息        │ 文档上下文│
└────────────────┴───────────────────────────────┴────────┘
```

- `SidebarConsole` 管目录、搜索、列表、分页、主题和账号入口。
- `DetailSurface` 管当前对象的概览、AI 操作、评分、洞察、Prompt、图谱和工具信息。
- `DocPanel` 管当前对象的文档、翻译和文件树。
- 主内容列始终是 `minmax(0, 1fr)`，所有网格子项都要允许收缩。
- 左右面板可折叠为窄轨，折叠不清空选择、搜索、分页或文档 tab 状态。

## 颜色标准

颜色只使用语义 token：

| Token | 用途 |
|---|---|
| `--bg` | 页面背景 |
| `--panel` | 卡片、弹窗、文档面板 |
| `--panel-strong` | 控件、弱强调背景 |
| `--line` | 边框和分割线 |
| `--text` | 主文字 |
| `--muted` | 辅助文字 |
| `--accent` | 主操作、选中态 |
| `--document` | 文档、文件树 |
| `--analysis` | AI、模型洞察 |
| `--danger` | 删除、错误 |
| `--success` | 成功、可用 |

不要在组件里写一次性主题色。新增状态先补 token，再写组件样式。

## 密度与文本标准

- 控件高度以 24 / 28 / 32 / 36px 为主，不使用营销页大按钮。
- 卡片标题保持工作台字号，不使用 Hero 级排版。
- `letter-spacing` 保持 0，兼顾中文和英文。
- 路径、文件名、对象名称、Prompt、Markdown、图谱节点都必须处理溢出。
- 操作文案使用短动词：扫描、添加、删除、评估、翻译、保存。

## 组件视觉标准

- Card 只承载明确的信息单元，不嵌套卡片。
- Button 使用语义变体：primary、outline、destructive、ghost / icon。
- Badge 只展示短状态或数量，不放长句。
- Tabs 只用于 `DocPanel` 内部切换，激活态用底部 2px 色条。
- Dialog 只承载短流程；长流程进入主区或右侧面板。

## 图谱标准

- 图谱必须在独立滚动容器中渲染，不能撑破主布局。
- 节点固定宽高，节点文本使用截断或多行 clamp。
- 选中节点和详情面板联动。
- 缩放控件固定在图谱右下角。
- 拖拽画布不能误触发节点点击。

## 文档和文件树标准

- Markdown 标题用左侧 3px 色条区分层级。
- 代码块允许换行，长命令不能撑破面板。
- 表格必须有横向滚动容器。
- 文件树每行三列：展开位、图标、名称。
- 目录在文件前，名称必须 `min-width: 0` 并截断。

## 可访问性标准

- 图标按钮必须有 `aria-label` 和 `title`。
- 折叠按钮维护 `aria-expanded`。
- 列表使用 `role="listbox"` / `role="option"` / `aria-selected`。
- Tabs 使用 `role="tablist"` / `role="tab"` / `aria-selected`。
- Dialog 有标题并使用 `aria-modal="true"`。
- 状态不能只靠颜色表达，必须同时有文本、符号或图标。
